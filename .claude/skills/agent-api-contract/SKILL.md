# Agent API Contract Skill

## Activation Contract

Invoke when touching: `src/lib/api/generated/`, `src/lib/api/client.ts` (aiClient/LeasefyAIClient section), `NEXT_PUBLIC_AGENT_URL`, `NEXT_PUBLIC_USE_MOCK_API`, `pnpm api:gen`, or any direct `fetch` to the agent microservice.

## Hard Rules

- **NEVER edit `src/lib/api/generated/agent.ts` by hand.** It is auto-generated by `openapi-typescript` from the agent's OpenAPI spec. Run `pnpm api:gen` and commit the result. Any manual change will be overwritten on the next regeneration.
- `api:check` is a **manual local gate only** — it does NOT run in CI. Stale generated types will not be caught automatically. Run `pnpm api:check` before any PR that might affect the agent contract.
- `src/lib/api/generated/agency.ts`, `cartera.ts`, and `cotizador.ts` are hand-authored convenience wrappers that re-export from `agent.ts`. Extend those files when adding new domain aliases — do not import from `agent.ts` directly in application code.
- The `aiClient` (`LeasefyAIClient`) has NO Bearer token wired yet — `getAuthHeaders()` only sends `Content-Type`. The auth TODO comment at `client.ts:~129` references "Clerk session" which does not apply to this project. Do not assume the aiClient authenticates requests.
- The general `apiClient` uses a module-level in-memory token set by `AuthProvider` via `setAccessToken(token)`. Token is NOT fetched per-request from Supabase to avoid `getSession()` hangs.
- Mock mode default: `NEXT_PUBLIC_USE_MOCK_API` defaults to mock when unset (`config.ts:35`: `!== 'false'`). Set `NEXT_PUBLIC_USE_MOCK_API=false` in `.env.local` to hit the real agent.
- Direct `fetch` calls to `NEXT_PUBLIC_AGENT_URL` are the pattern (not `apiClient`/`aiClient`) for most agent endpoints — see 20+ call sites across `src/app/panel/inmobiliaria/ai/`.

## Decision Gates

- Changing an agent endpoint? Regenerate: `pnpm api:gen` (requires agent dev server running at `:4000`, or uses committed snapshot). Commit the updated `agent.ts`.
- Adding a new domain to the generated types? Add a new hand-authored wrapper (like `cartera.ts`) that re-exports specific types from `agent.ts`. Update `index.ts` barrel.
- New direct `fetch` to agent? Use `process.env.NEXT_PUBLIC_AGENT_URL` as base URL. Follow the pattern in `src/app/panel/inmobiliaria/ai/` pages — no wrapper client needed for one-off calls.
- Need mock behavior? Set `NEXT_PUBLIC_USE_MOCK_API` to anything other than `'false'`. Mock implementations live in `src/lib/api/mock.ts` + data files under `src/lib/api/`.
- PR touches generated types? Run `pnpm api:check` locally before pushing — CI will NOT catch stale types.
- Agent unreachable during `api:gen`? Script falls back to `scripts/openapi-snapshot.json` automatically. Update the snapshot file when the spec changes significantly.

## Execution Steps

1. Before any agent-contract work, confirm the agent dev server is running at `localhost:4000`.
2. Run `pnpm api:gen` — script tries live URL first, falls back to snapshot.
3. If new types are needed in application code, add convenience aliases to the appropriate wrapper file (`agency.ts`, `cartera.ts`, or `cotizador.ts`).
4. Update any call sites that use the changed endpoints.
5. Run `pnpm api:check` and confirm exit code 0 before committing.
6. Run `pnpm exec tsc --noEmit` to catch type errors from the regenerated types.

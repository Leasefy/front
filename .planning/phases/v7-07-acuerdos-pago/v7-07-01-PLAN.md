<objective>
Land the v7-07 CONTRACT FOUNDATION: the tenant-scoped acuerdo types (re-exported from the agent schema, never
forked) and a tolerant, BFF-forwarded `tenant-acuerdos.service.ts` — all unit-tested. Nothing here is a live
backend call today (the tenant RLS routes are the HARD cross-repo dependency); everything degrades honestly so
the acuerdo surfaces (waves 2-5) build on stable seams and never fabricate an acuerdo, cuota, acceptance, or
checkout URL on a real-tenant path.

Two honest deliverables:
1. **Re-export the record shape (ACUE-01 crux, A5/PITFALLS 9).** `tenant-acuerdos.types.ts` RE-EXPORTS the
   generated `CarteraPaymentPlanDetailResponse` / `CarteraPaymentPlanAcceptResponse` as `AcuerdoDetail` /
   `AcuerdoAcceptResult`, derives `AcuerdoInstallment = AcuerdoDetail['installments'][number]` (keeps
   `number/dueDate/amountCop/status/paidAt` verbatim so a cuota row maps 1:1), and adds only the small tenant
   INPUT types (`AcuerdoAcceptInput`, `PremoraPlanRequestInput`). A grep gate forbids any re-declared
   `interface CarteraPaymentPlan*` (the v7-06 fork lesson — one source of truth for saldo).
2. **Tolerant BFF contract (ACUE-01/02/03/04, A6).** `tenant-acuerdos.service.ts` modeled 1:1 on
   `pqrs.service.ts` + `agent-contact.service.ts`: `listMine()` → `[]` on 404/403/0 (never a fabricated
   acuerdo); `getMine(id)` resolves from `listMine().find` (own-only, NO fetch-by-id → no IDOR);
   `getCuotaPaymentUrl(planId, cuotaNumber?)` → `null` on not-live (the paymentUrl is SERVER-provided, the
   client never builds a checkout amount); `accept()` + `requestPremoraPlan()` throw a typed
   `AcuerdoUnavailableError` on not-live — NEVER a fake "aceptado" / fabricated plan. Every call goes through
   `apiClient` (→ `NEXT_PUBLIC_BACKEND_URL`, the BFF), NEVER the agency's `NEXT_PUBLIC_AGENT_URL` /
   `/api/agency/:agencyId` bearer path (A6, IDOR).

This is wave 1: it seeds the types/service that waves 2-5 consume. Depends on nothing.

Purpose: ACUE-01..04 contract foundation, frontend-first, re-using the agent's single payment-plan record.
Output: re-exported types + tolerant BFF service, unit-tested.

**Guardrails (A5 + A6 are the two that must never be optimized away):** re-export not re-declare (grep-gated);
apiClient/BFF only, never the agency `NEXT_PUBLIC_AGENT_URL` / `/api/agency` path (A6); NO client policy check /
auto-approve / terms edit (A5 — the agent owns `requiresHumanReview()`); `listMine()→[]` (no fabricated rows);
`getMine` resolve-from-list (no fetch-by-id); server-provided paymentUrl only (no client cuota amount); es-CO;
zero new npm packages.

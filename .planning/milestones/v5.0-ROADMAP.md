## Milestone Summary

**Key Decisions:**

- `apiClient` has no `.put()` — use `.patch()` for PATCH requests (matches existing pattern)
- Zod not installed — TypeScript validation helpers in `src/lib/validation/` following `applicationValidation.ts` pattern
- `AlertCircle` does not exist in @phosphor-icons/react — use `Warning` icon
- `INMOBILIARIA` BackendRole maps to `'agency'` frontend role (alongside `AGENT`)
- `agencyApi` namespace added to `inmobiliaria.service.ts` (not a separate service file)
- Canonical types (`InvitationInfo`, `OnboardingStep`, `AgencyOnboardingStatus`) live in `inmobiliaria.ts`
- Middleware is pass-through only — documents public routes for future server-side auth
- MOCK_STEPS in `useAgencyOnboardingStatus` remains — swap for `agencyApi.getOnboardingStatus()` when backend deploys

**Issues Resolved:**

- `apiClient.put()` not available → auto-fixed to `.patch()`
- `AlertCircle` Phosphor import error → auto-fixed to `Warning`
- Hook naming collision with tenant `use-onboarding-status.ts` → named `useAgencyOnboardingStatus`

**Issues Deferred:**

- Pre-existing Server Components prerender errors on `/`, `/auth`, `/pricing` — outside scope
- Real backend integration (agencyApi methods currently hit real API if deployed, mock data in hooks otherwise)

**Technical Debt:**

- `MOCK_STEPS` array in `useAgencyOnboardingStatus.ts` needs swap for `agencyApi.getOnboardingStatus()` when backend Phase 23 deploys
- `AgencySetupWizard` API calls are non-blocking (try/catch proceeds on failure) — assumes backend may not be deployed

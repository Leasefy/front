### Task 3: Verify chat integration (BRFG-04)

**Files:**
- MODIFY `src/lib/hooks/useBetaChat.ts` — Ensure sendBriefingAction switches tab properly

**Verification:**
- `sendBriefingAction` must:
  1. Switch `activeTab` to 'conversations' — requires BetaLayout to expose tab control
  2. Call `sendMessage(actionContext)` to start a contextual chat

**Implementation approach:**
- Since `activeTab` state lives in BetaLayout (not in useBetaChat), add an `onNavigateToChat` callback that BetaLayout can wire
- Alternative (simpler): `sendBriefingAction` calls `sendMessage()` directly, and the user sees the response when they switch to conversations tab manually. The action button text changes to "Enviado ✓" to confirm.
- **Chosen approach**: Add `onTabChange` callback to useBetaChat context so sendBriefingAction can trigger tab switch. BetaLayout passes setActiveTab into BetaChatProvider.

**BetaChatProvider/BetaLayout changes:**
- BetaChatProvider accepts optional `onTabChange?: (tab: string) => void` prop
- BetaLayout passes `setActiveTab` to BetaChatProvider
- `sendBriefingAction` calls `onTabChange('conversations')` then `sendMessage(context)`

**Acceptance criteria:**
- Clicking "Cuéntame mas sobre cobros" switches to conversations tab
- A user message is sent with the section's context
- Normal chat flow continues (mock response appears)
- Works for all 4 briefing sections

## Integration Points

- `onTabChange` callback pattern enables future features (e.g., decision notification click → switch tab)
- Briefing history data structure informs API client types (Phase 24)
- Mock briefing dates are deterministic (relative to "today") for consistent testing

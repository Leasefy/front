# Plan 21-01: Decision Card Component with Options, Recommendations, and Selection

## Goal

Create the DecisionCard component that renders inline in the chat conversation with 2-4 selectable options, each showing an AI recommendation indicator (recommended/neutral/not recommended). When user selects an option, it sends as their response and the card becomes read-only showing the chosen option.

## Requirements Addressed

- **DCSN-01**: Pending decision cards embedded in conversation with 2-4 options
- **DCSN-02**: Each option shows AI recommendation indicator (recommended/neutral/not recommended)
- **DCSN-03**: User can select an option which sends it as their response
- **DCSN-04**: Decision cards become read-only after selection (shows what was chosen)

## Tasks

### Task 1: Decision type definitions and mock data

**Files:**
- MODIFY `src/lib/types/beta-chat.ts` — Add decision types
- CREATE `src/lib/data/mock-decisions.ts` — Mock decision scenarios

**Type additions to beta-chat.ts:**
- `DecisionRecommendation = 'recommended' | 'neutral' | 'not_recommended'`
- `DecisionOption`: `{ id: string; label: string; description: string; recommendation: DecisionRecommendation }`
- `PendingDecision`: `{ id: string; title: string; description: string; options: DecisionOption[]; selectedOptionId?: string; selectedAt?: Date; category: AgentType }`
- Extend `ChatMessage` with optional `decision?: PendingDecision`

**Mock decisions (mock-decisions.ts):**
- `getMockDecisionScenario(userMessage)` — keyword matcher returning a PendingDecision or null
- Scenarios:
  - "renovar" / "renovacion" → Renovar contrato (3 options: renovar IPC, negociar, no renovar)
  - "aprobar" / "candidato" / "score" → Aprobar candidato score 78 (3 options: aprobar, rechazar, solicitar mas info)
  - "reparacion" / "autorizar" / "presupuesto" → Autorizar reparacion $450K (3 options: autorizar, buscar otro proveedor, diferir)
  - "mora" / "cobro formal" → Accion sobre mora (4 options: recordatorio, cobro formal, negociar plan, iniciar proceso)
  - "decision" / "decisiones" → Renovar contrato (default decision for generic decision queries)

**Acceptance criteria:**
- Types compile cleanly with existing ChatMessage interface
- Mock data returns realistic Colombian rental decisions
- Each scenario has 2-4 options with varied recommendation levels

### Task 2: DecisionCard component and ChatContainer integration

**Files:**
- CREATE `src/components/beta/DecisionCard.tsx` — Decision card component
- MODIFY `src/lib/hooks/useBetaChat.ts` — Decision detection and selection handling
- MODIFY `src/components/beta/ChatContainer.tsx` — Render DecisionCard inline

**DecisionCard component:**
- Props: `decision: PendingDecision; onSelect?: (optionId: string) => void`
- Header: decision title + category badge (using AGENT_METADATA colors)
- Description text explaining the decision context
- Options as selectable cards/buttons:
  - Each option: label, description, recommendation indicator
  - Recommendation indicators: green "Recomendado" badge, gray "Neutral", red/orange "No recomendado"
  - Hover state highlights the option
  - Click triggers `onSelect(optionId)`
- Read-only state (when `selectedOptionId` is set):
  - Selected option highlighted with checkmark
  - Non-selected options dimmed/muted
  - "Decidido" timestamp shown
  - onSelect callback not called (no interaction)
- Visual style: card with left border color from category, rounded corners, compact
- Smooth transition between interactive and read-only states

**useBetaChat changes:**
- In `sendMessage`, after agent scenario check: also check `getMockDecisionScenario(trimmed)`
- If decision scenario found: attach decision to the assistant message
- New function: `selectDecisionOption(messageId: string, optionId: string)`:
  1. Updates the decision's `selectedOptionId` and `selectedAt`
  2. Adds a user message: "He seleccionado: [option label]"
  3. Triggers a new mock response acknowledging the decision
- Expose `selectDecisionOption` in UseBetaChatReturn

**ChatContainer changes:**
- After agent result cards, before AssistantBubble: render DecisionCard if `message.decision` exists
- Wire `onSelect` to `selectDecisionOption`
- Read-only decisions render without onSelect

**Acceptance criteria:**
- Decision card renders inline in conversation flow
- Options are clickable with recommendation indicators
- Selecting an option marks card as read-only and sends user response
- Existing chat features (streaming, agents, conversations) unchanged
- TypeScript clean build

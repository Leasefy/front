<objective>
Wire the ACUERDO DATA LAYER into the existing v7-03 case hub (ACUE-01). This fills the exact seam v7-03 left
open — the `CaseType` union already declares `'acuerdo'` with zero rows (`tenant-case.ts:53`) — so approved
acuerdos become real cases the moment `acuerdosApi.listMine()` returns records, with NO rework of the aggregator
and NO change to the agency side. Copies the v7-06 PQRS move exactly.

Three honest deliverables:
1. **Pure acuerdo→case mappers (ACUE-01).** In `tenant-case.ts` add `acuerdoStatusToTone(status: string):
   CaseTone` (`offered`→`'attention'` — the tenant may need to accept; `active`→`'info'`;
   `completed`/`cancelled`→`'neutral'`; unknown → `'info'`, NEVER alarm) + `acuerdoStatusToLabel(status:
   string): string` (factual es-CO labels with a safe default; no credit-bureau/urgency copy) + an OPTIONAL
   `TenantCase.acuerdo` metadata block + `acuerdoToCase(p: AcuerdoDetail): TenantCase`. The mapper PASSES THROUGH
   the raw plan record (`status`, `totalDueCop`, `installments`, `paymentUrl`, `acceptedAt`) — it does NOT
   compute a saldo (PITFALLS 9). `detailLink` = `/inquilino/acuerdos/${planId}` (the dedicated interactive
   detail); `sourceLink` = `/inquilino/acuerdos`. Reuse `AcuerdoDetail`/`AcuerdoInstallment` from
   `@/lib/api/tenant-acuerdos.types` (never a parallel model).
2. **Tolerant list hook (ACUE-01).** `use-tenant-acuerdos.ts` mirrors `useTenantPqrs` exactly (useState list +
   isLoading + error + refetch, useEffect fetch), sourced from `acuerdosApi.listMine()` → `[]` on unavailable.
   No internal poller (the aggregator owns the tab-gated refresh).
3. **Fold into the aggregator (ACUE-01).** `use-tenant-cases.ts` composes `useTenantAcuerdos`, pushes
   `acuerdoToCase(p)` rows in the `useMemo` right after the PQRS loop (where the comment reads "acuerdo/contrato
   still emit no rows"), and extends `refetch`'s `Promise.all` + the `error ??` chain (acuerdo appended LAST so
   pago/aplicacion/pqrs errors keep priority). `[]` → zero rows → the hub's Acuerdos "Próximamente" stays.

Depends on v7-07-01 (acuerdosApi + tenant-acuerdos.types). This is wave 2: waves 3-5 (list/detail/accept/pay)
build on these mappers + hook.

Purpose: ACUE-01 — fold approved acuerdos into the unified caso hub, honestly (no second saldo engine).
Output: pure acuerdo mappers + tolerant list hook + aggregator fold, unit-tested.

**Guardrails:** reuse `AcuerdoDetail`/`AcuerdoInstallment` (no fork); no alarm tone (CaseTone capped at
attention); normalize-never-compute (no saldo math — pass-through only, PITFALLS 9); `[]` → zero rows (no
fabricated cases); own-cases-only (listMine is JWT-scoped); no internal fields (`debtorId`/audit) leak into
TenantCase; `detailLink` → the dedicated acuerdo detail; es-CO labels; zero new npm packages.
</objective>

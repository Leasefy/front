- MODIFY `src/components/beta/PreferencesPanel.tsx`
- MODIFY `src/components/beta/ChatContainer.tsx`

**Strategy:**

These components currently render content immediately from mock data/state. Add loading state handling:

1. **For hook-based components** (using `useBetaChat`):
   - Add `isLoading` check at the top
   - Render skeleton while loading
   - This prepares for real API where data fetching has latency

2. **For direct-render components** (BriefingCard, preferences):
   - Add `isLoading` prop (optional, defaults to false)
   - When true, render corresponding skeleton
   - Mock layer can simulate brief loading delay

3. **Pattern:**
   ```tsx
   if (isLoading) return <ConversationListSkeleton />;
   if (error) return <ErrorDisplay error={error} onRetry={retry} />;
   // ... normal render
   ```

**Acceptance criteria:**
- Each data view has loading → content transition
- No blank/empty flash during data loading
- Loading state visible for at least 300ms (prevents flicker)
- Loading and content have same dimensions (no layout shift)

### Task 3: Error boundary component

**Files:**
- CREATE `src/components/beta/BetaErrorBoundary.tsx`

**Implementation:**

```tsx
'use client';

import React, { Component, type ErrorInfo, type ReactNode } from 'react';
import { WarningCircle, ArrowClockwise } from '@phosphor-icons/react';

interface Props {
  children: ReactNode;
  fallback?: ReactNode;
}

interface State {
  hasError: boolean;
  error: Error | null;
}

export class BetaErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false, error: null };

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    console.error('[BetaErrorBoundary]', error, errorInfo);
  }

  handleRetry = () => {
    this.setState({ hasError: false, error: null });
  };

  render() {
    if (this.state.hasError) {
      if (this.props.fallback) return this.props.fallback;

      return (
        <div className="flex flex-col items-center justify-center h-full px-6 py-12">
          <WarningCircle className="w-12 h-12 text-red-400 mb-4" weight="fill" />
          <h2 className="text-lg font-semibold text-foreground mb-2">
            Algo salió mal
          </h2>
          <p className="text-sm text-muted-foreground text-center max-w-sm mb-6">
            Ocurrió un error inesperado. Puedes intentar de nuevo o recargar la página.
          </p>
          <button
            onClick={this.handleRetry}
            className="flex items-center gap-2 px-4 py-2 rounded-lg
                       bg-indigo-500 text-white hover:bg-indigo-600
                       text-sm font-medium transition-colors"
          >
            <ArrowClockwise className="w-4 h-4" />
            Intentar de nuevo
          </button>
        </div>
      );
    }

    return this.props.children;
  }
}
```

Note: Error boundary strings should also use i18n, but since this is a class component, we'll pass translated strings via fallback prop or use a wrapper functional component. The default fallback uses Spanish (primary locale).

**Acceptance criteria:**
- Class component implements getDerivedStateFromError + componentDidCatch
- Default fallback shows error icon, message, retry button
- Retry resets error state and re-renders children
- Dark mode compatible styling
- Error logged to console for debugging

### Task 4: Wire error boundaries into Beta layout

**Files:**
- MODIFY `src/components/beta/BetaLayout.tsx`
- MODIFY `src/app/panel/beta/layout.tsx`
- MODIFY `src/app/panel/inmobiliaria/beta/layout.tsx`

**Strategy:**

Wrap at two levels:
1. **Outer boundary** in route layout files — catches page-level errors
2. **Inner boundaries** in BetaLayout — catches sidebar vs main content independently

```tsx
// In BetaLayout
<BetaErrorBoundary>
  <div className="hidden md:flex">
    <BetaSidebar ... />
  </div>
</BetaErrorBoundary>

<BetaErrorBoundary>
  <main className="flex-1 overflow-y-auto">
    {activeTab === 'settings' ? <PreferencesPanel /> : children}
  </main>
</BetaErrorBoundary>
```

This ensures a sidebar error doesn't crash the chat, and vice versa.

**Acceptance criteria:**
- Sidebar errors don't crash main content
- Main content errors don't crash sidebar
- Page-level boundary catches unhandled errors
- Retry button recovers from transient errors

### Task 5: TypeScript strict + build validation

**Files:**
- CHECK `tsconfig.json` for strict mode settings
- FIX any TypeScript errors in `src/components/beta/**`
- FIX any TypeScript errors in `src/lib/api/**`
- FIX any TypeScript errors in `src/hooks/useBeta*`

**Process:**

1. Run `npx tsc --noEmit` and capture ALL errors
2. Focus on Beta-related files only (don't fix unrelated v1/v2/v3 issues)
3. Fix each error:
   - Missing types → add explicit types
   - `any` types → replace with proper types
   - Unused imports → remove
   - Missing null checks → add guards

4. Run `next build` to verify:
   - Zero build errors
   - Zero build warnings in Beta files
   - All pages compile successfully

5. Run `npx next lint` for ESLint:
   - Fix any warnings in Beta components
   - Ensure no unused variables
   - Ensure no missing dependencies in hooks

**Acceptance criteria:**
- `npx tsc --noEmit` passes with zero errors (or no NEW errors from Beta)
- `next build` completes successfully
- `next lint` shows no warnings for Beta files
- No `any` types in Beta components or API client
- No unused imports or variables

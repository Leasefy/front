# Requirements — v6.0 Backoffice Unificado ERP·CRM·Autopilot (Frontend-First)

**Milestone:** v6.0
**Created:** 2026-05-29
**Principle:** Construir **todas las secciones del ERP en el frontend** del panel inmobiliaria, de forma **aditiva y no-destructiva**. Cada sección es UI real + contrato de api-client (tipos) con estado vacío/placeholder honesto; el motor (backend M1–M3 / proveedor DIAN) la llena por detrás. La inmobiliaria ve un ERP+CRM+Autopilot completo desde ya.
**Program backbone:** `.planning/ERP-CRM-AUTOPILOT-PROGRAM.md` · **Gap analysis:** `.planning/research/ERP-VISION/GAP-ANALYSIS.md`

> ⛔ Restricción dura: NO romper el CRM/módulos existentes. Todo entra como rutas/módulos nuevos vía el sistema de permisos (`canAccess(module,'view')`). Leer `docs/DESIGN.md` antes de cualquier UI.

---

## Requirements (este milestone)

### UNIF — Unificación & Command Center (v6-01)
- [ ] **UNIF-01**: La nav agrupa los módulos en bloques (Comercial/CRM · Financiero/ERP · Autopilot/IA · Documentos · Operación) sin eliminar ningún módulo ni ruta existente.
- [ ] **UNIF-02**: Existe un landing "Operación / Hoy" que presenta el panel como un solo sistema ERP+CRM+Autopilot con accesos a cada bloque.
- [ ] **UNIF-03**: Las secciones ERP nuevas aparecen en la nav con su estado (activa / próximamente) vía `canAccess(module,'view')`.
- [ ] **UNIF-04**: El usuario llega a cualquier sección ERP/CRM/Autopilot desde un punto de entrada único y coherente.

### FACT — Facturación (v6-02) ⭐
- [ ] **FACT-01**: El usuario puede ver y crear facturas de venta por conceptos distintos al canon (reparaciones, honorarios, cobros extraordinarios, servicios).
- [ ] **FACT-02**: El usuario puede ver y registrar facturas de compra de proveedores con estado de pago (vencida / a crédito / pendiente).
- [ ] **FACT-03**: El usuario puede ver el estado de facturación electrónica (DIAN / CUFE) de cada factura.
- [ ] **FACT-04**: El usuario puede crear notas débito/crédito asociadas a una factura.
- [ ] **FACT-05**: El usuario puede ver la facturación recurrente del periodo (canon→inquilino, administración→propietario) con sus conceptos e impuestos.
- [ ] **FACT-06**: Cada vista de facturación está cableada a un contrato de api-client (tipos) con estado vacío honesto hasta que el motor (M2) lo implemente.

### CONC — Conciliación bancaria (v6-03)
- [ ] **CONC-01**: El usuario puede crear una conciliación y cargar una fuente bancaria (archivo Bancolombia / multi-fuente).
- [ ] **CONC-02**: El sistema muestra coincidencias sugeridas entre movimientos y obligaciones (tercero / referencia / contrato / valor).
- [ ] **CONC-03**: El usuario puede confirmar o rechazar cada coincidencia sugerida.
- [ ] **CONC-04**: La vista distingue pagos completos, parciales, duplicados, no identificados, diferencias de valor y fuera de fecha.
- [ ] **CONC-05**: Existe una cola de revisión manual para movimientos no conciliados automáticamente.

### EGR — Egresos a propietarios / Tesorería (v6-04)
- [ ] **EGR-01**: El usuario puede ver el egreso a propietario con desglose: canon recibido − comisión admin − IVA comisión − descuentos = neto.
- [ ] **EGR-02**: El usuario puede generar/ver el comprobante de egreso por propietario.
- [ ] **EGR-03**: El usuario puede ver la cuenta destino del propietario asociada al egreso.
- [ ] **EGR-04**: La sección se construye sobre `dispersiones` existente sin romper su flujo actual.

### INFO — Informes & Insights (v6-05)
- [ ] **INFO-01**: El usuario puede consultar el catálogo de informes administrativos (terceros, propiedades por tercero, contratos por detalle, próximos a vencer, terminados).
- [ ] **INFO-02**: El usuario puede consultar informes contables/financieros (cartera inquilinos/propietarios, pagos pendientes, IVA y comisiones, liquidación de servicios públicos).
- [ ] **INFO-03**: El usuario puede exportar documentos contables (formato Helisa) y certificado tributario de propietarios.
- [ ] **INFO-04**: Existe una capa de "Insights & Alertas" que convierte la data en acción ("18 contratos por vencer, 6 sin gestión"; "$84M por dispersar, cubres 62%").
- [ ] **INFO-05**: Cada insight enlaza a la acción correspondiente (cobranza, renovación, egreso, etc.).

### PQRS — PQRS / Solicitudes + Agenda (v6-06)
- [ ] **PQRS-01**: El usuario puede registrar una PQRS/solicitud (quién, tipo, inmueble/contrato, asignado, estado, respuesta).
- [ ] **PQRS-02**: El usuario puede asignar, dar seguimiento y cerrar una PQRS.
- [ ] **PQRS-03**: Una reparación reportada puede pasar al flujo de cotización con proveedor.
- [ ] **AGEN-01**: Existe una agenda interna que muestra eventos del sistema (visitas, firmas pendientes, vencimientos, seguimientos, inspecciones).
- [ ] **AGEN-02**: El usuario puede crear tareas y verlas asociadas a contratos/propiedades/terceros.

### TERC — Creación de terceros por IA (v6-07)
- [ ] **TERC-01**: El usuario puede iniciar la creación de un tercero subiendo foto de cédula/RUT o un audio.
- [ ] **TERC-02**: El sistema extrae los datos (vía `agent`) y prellena el formulario de tercero.
- [ ] **TERC-03**: El usuario revisa, corrige y guarda el tercero en menos pasos que el flujo manual actual.
- [ ] **TERC-04**: El flujo manual existente de creación de terceros sigue disponible y sin cambios.

### CAPT — Captura de propiedad foto+audio (v6-08, stretch)
- [ ] **CAPT-01**: El asesor puede capturar una propiedad subiendo fotos + un audio descriptivo (móvil-friendly).
- [ ] **CAPT-02**: El sistema transcribe el audio y extrae características estructuradas (tipo, barrio, habitaciones, baños, canon, admin, restricciones).
- [ ] **CAPT-03**: El sistema sugiere una descripción comercial y prellena la ficha para revisión.
- [ ] **CAPT-04**: El asesor revisa y publica/guarda; el flujo de creación de propiedades existente sigue intacto.

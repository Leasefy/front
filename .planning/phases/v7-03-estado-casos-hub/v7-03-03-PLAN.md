<objective>
Ship the **case detail + state timeline** at `/inquilino/casos/[caseId]` (CASO-02). The detail
resolves its case by filtering the tenant's OWN aggregated `useTenantCases()` list by the route
`caseId` — it never fetches by a tenant-supplied raw id, so own-cases-only / no-IDOR is inherited
from the JWT-scoped source hooks. It composes a neutral status badge + a summary + a **state
timeline** built from `case.events[]` (which v7-03-01 derived from real source timestamps only),
reusing the generic `PlanActivityTimeline`. It out-links to the source surface for the full record.

Non-negotiables encoded here:
- **Timeline from source timestamps only** — render `case.events[]` as-is; do NOT copy the legacy
  `ApplicationTimeline` client-synthesis path (it invents "created → reviewed → approved" steps with
  made-up timestamps and is unused on real pages). No invented milestones (PITFALLS 2 / R2).
- **Own-cases-only (CASO-02)** — resolve via `cases.find(c => c.id === caseId)`; a miss → honest
  "Caso no encontrado" empty-state; NEVER call an API with a raw route id.
- **No internal leakage** — show `responsable` as a ROLE ("Inmobiliaria"), opaque UUID id; no
  `responsableId`, no agency notes (they are not on `TenantCase` by construction — keep it that way).
- **Neutral tone (CASO-04)** — badge capped at neutral/info/attention (never destructive); no
  countdown, no "Datacrédito"/urgency copy.

Also fix the `es-CL` → `es-CO` date-locale bug in `PlanActivityTimeline` (DESIGN.md §16; same fix
precedent as v7-02). This is a genuine Colombian-locale correction; the component's neutral
`text-plan-*` grey tokens render acceptably in the tenant portal (R5) — if visually off, wrap the
timeline in a thin tenant-styled container rather than restyling the shared primitive.

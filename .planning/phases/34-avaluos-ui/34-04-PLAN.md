<task type="auto">
  <name>Task 1: useAvaluoStatus polling hook</name>
  <files>src/lib/hooks/use-avaluo-status.ts</files>
  <action>
    Create a client hook mirroring the setInterval-in-useEffect pattern from
    use-agent-activity.ts. Import `getAvaluoStatus` from `@/lib/api/avaluo.service`,
    `TERMINAL_STATUSES` + `AvaluoStatusResponse` from `@/lib/types/avaluo`.

    `useAvaluoStatus(submissionId: string | null)`:
    - State: `statusData: AvaluoStatusResponse | null`, `isLoading: boolean` (start true).
    - useEffect keyed on `[submissionId, statusData?.status]`:
      - If `!submissionId`, return.
      - If `statusData && TERMINAL_STATUSES.includes(statusData.status)`, return WITHOUT
        scheduling another interval (stop polling on terminal states — this is the key leak
        guard).
      - Define `async function poll() { const res = await getAvaluoStatus(submissionId);
        setStatusData(res); setIsLoading(false); }` wrapped in try/catch (on error just
        setIsLoading(false), keep last status).
      - Call poll() immediately, then `const id = setInterval(poll, 15_000)`.
      - CRITICAL: `return () => clearInterval(id)` — always clean up to avoid setting state
        on an unmounted component.
    - Return `{ statusData, isLoading }`.

    Add a comment: "Polls every 15s; stops on terminal states (entregado/rechazado).
    Status endpoint is mocked in the service until backend exposes it."
  </action>
  <verify>npx tsc --noEmit passes; hook returns { statusData, isLoading }; rg confirms clearInterval cleanup and a terminal-state early return.</verify>
  <done>Hook polls every 15s, stops on terminal states, and clears the interval on unmount/dep change.</done>
</task>

<task type="auto">
  <name>Task 2: AvaluoEstadoCard + WompiPayButton</name>
  <files>src/components/avaluo/AvaluoEstadoCard.tsx, src/components/avaluo/WompiPayButton.tsx</files>
  <action>
    READ docs/DESIGN.md first.

    `WompiPayButton.tsx` (`'use client'`):
    - Props: `{ submissionId: string }`.
    - A primary Button labelled "PAGAR CERTIFICADO" (uppercase per DESIGN.md).
    - On click: POST to `/api/avaluo/wompi-session` with JSON `{ submissionId }` →
      receive `{ reference, amountInCents, currency, integrity, publicKey }`. Then build the
      Wompi hosted-checkout URL and redirect:
      ```
      const redirectUrl = `${window.location.origin}/avaluo/estado/${submissionId}`;
      const url = `https://checkout.wompi.co/p/?public-key=${publicKey}`
        + `&currency=${currency}&amount-in-cents=${amountInCents}`
        + `&reference=${reference}&signature:integrity=${integrity}`
        + `&redirect-url=${encodeURIComponent(redirectUrl)}`;
      window.location.href = url;
      ```
      (Note Wompi's param is `signature:integrity`.) Show a loading state on the button while
      fetching the session. On fetch error, toast.error and re-enable the button.
    - Comment: integrity comes from the server route — never computed here.

    `AvaluoEstadoCard.tsx` (`'use client'`):
    - Props: `{ submissionId: string; statusData: AvaluoStatusResponse | null; isLoading: boolean }`.
    - While `isLoading && !statusData`, show a skeleton/loading state.
    - Render the status as a `<Badge variant={STATUS_BADGE[status].variant}>
      {STATUS_BADGE[status].label}</Badge>` (import STATUS_BADGE from types).
    - Conditional CTA region:
      - status === 'firmado' → render `<WompiPayButton submissionId={submissionId} />`.
      - status === 'entregado' → if `statusData.downloadUrl` exists, render a primary
        "DESCARGAR CERTIFICADO" link to it; also link to the public verificar page if
        `statusData.slug` exists (`/avaluo/verificar/{slug}`).
      - status === 'rechazado' → show a destructive note explaining the request was rejected.
      - other states → show a neutral "Estamos procesando tu avalúo" helper.
    - Show a small "Se actualiza automáticamente" hint while non-terminal.

    The pay button must NEVER render for any state other than 'firmado'.
  </action>
  <verify>npx tsc --noEmit passes; rg confirms WompiPayButton only rendered under status === 'firmado' in AvaluoEstadoCard; WompiPayButton posts to /api/avaluo/wompi-session.</verify>
  <done>Status card maps all 6 states to badges; pay button shows only on 'firmado' and redirects to Wompi using the server-computed integrity; download/verify CTA shows on 'entregado'.</done>
</task>

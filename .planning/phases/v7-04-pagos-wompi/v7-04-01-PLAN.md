<objective>
Ship the **security core** of PAGO-02: a server-only route `POST /api/inquilino/pagos/wompi-session`
that issues a Wompi hosted-checkout session for rent, modeled **1:1** on the avalúo route
(`src/app/api/avaluo/wompi-session/route.ts`) for the integrity + secret discipline, with the
**one structural addition** rent needs: the amount is resolved **server-side** from NestJS
`GET /leases/:id/payment-info` under the tenant's forwarded JWT (the auth-forward idiom from
`src/app/api/docs/[documentId]/route.ts`), and a **period lock** blocks double-pay.

The avalúo route HARDCODES the amount (`5_000_000`, route.ts:35) and trusts nothing from the
client. Rent is variable (`monthlyRent`), so the route MUST look up the authoritative amount and
MUST NOT accept an `amount` from the request body (this removes the anti-pattern at
`PayRentModal.tsx:173` — that removal happens in v7-04-02; this plan builds the route that makes
it possible).

To keep the security-critical logic unit-testable without mocking `next/server` + `fetch`, the
period-lock, reference and checkout-URL logic live in a **client-safe pure helper**
(`src/lib/payments/wompi-rent-session.ts`, **NO `node:crypto`**), and the integrity **hash** lives in a
**separate server-only module** (`src/lib/payments/wompi-integrity.ts`, `import 'server-only'` +
`node:crypto`) — so the `'use client'` PayRentModal (v7-04-02) can import `buildWompiCheckoutUrl`
without pulling `node:crypto` into the client bundle (plan-checker Warning 1). The route orchestrates both.

Purpose: Satisfy PAGO-02's server-side-amount + integrity + period-lock invariants with the
secret never reaching the client.
Output: pure helper + its test + the new route.

**Guardrails (non-negotiable):** secret is server-only (no `NEXT_PUBLIC_`), hash server-only,
`runtime='nodejs'`, response returns only `{ reference, amountInCents, currency, integrity, publicKey }`
(never the secret), amount comes from `payment-info` (never the client), period lock enforced.
Zero new npm packages (integrity uses the `node:crypto` builtin, same as avalúo).
</objective>

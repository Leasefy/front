<task type="auto">
  <name>Task 2: Build the avaluo API service module</name>
  <files>src/lib/api/avaluo.service.ts</files>
  <action>
    Create a thin service module — all avalúo network calls live here, never in components.
    Base URL: `const AVALUO_URL = process.env.NEXT_PUBLIC_AVALUO_URL`.

    Export these async functions:

    1. `photoPresign(filename: string, contentType: string): Promise<PhotoPresignResponse>`
       - POST `${AVALUO_URL}/api/avaluo/photo-presign` with JSON body { filename, contentType }.
       - Return parsed { key, uploadUrl }.

    2. `uploadPhotoToS3(file: File): Promise<string>`
       - Calls photoPresign(file.name, file.type), then does a direct
         `PUT` to `uploadUrl` with `headers: { 'Content-Type': file.type }` and body `file`.
       - CRITICAL: the Content-Type header MUST equal file.type or S3 returns 403
         (the presigned URL is signed for that exact content type). Do NOT add auth headers
         to the S3 PUT — the presigned URL carries its own auth.
       - Throw `new Error('S3 upload failed: ' + res.status)` if PUT not ok. Return the `key`.

    3. `submitIntake(formData: AvaluoFormData): Promise<IntakeResponse>`
       - POST `${AVALUO_URL}/api/avaluo/intake` with JSON body mapping every AvaluoFormData
         field (address, city, propertyType, areaM2, estrato, bedrooms, bathrooms, features,
         geo, photoKeys, identity, policyVersion, purposeAvaluo, purposeDataset, purposeContacto).
       - Map non-OK statuses to typed errors: 429 → throw Error('rate_limit'),
         422 → throw Error('validation_error'), 503 → throw Error('service_unavailable'),
         other non-ok → throw Error('submit_error').
       - On 201, return parsed { id }.

    4. `getAvaluoStatus(submissionId: string): Promise<AvaluoStatusResponse>`
       - MOCK for now — the real status endpoint is TBD (per locked decision #7).
       - Implement with the REAL fetch shape so swapping to live is trivial:
         attempt `GET ${AVALUO_URL}/api/avaluo/estado/${submissionId}`; if the fetch fails
         or returns non-ok, fall back to a deterministic mock that returns
         `{ status: 'en_revisión' }` (so the polling UI has something to render in dev).
         Add a `// TODO: replace mock fallback when backend exposes status endpoint` comment.

    Import all types from `@/lib/types/avaluo`.
  </action>
  <verify>npx tsc --noEmit passes; module exports photoPresign, uploadPhotoToS3, submitIntake, getAvaluoStatus. Grep confirms PUT to S3 passes Content-Type: file.type.</verify>
  <done>Service compiles; submitIntake maps 422/429/503 to distinct errors; uploadPhotoToS3 sends Content-Type header; getAvaluoStatus has real fetch shape + mock fallback.</done>
</task>

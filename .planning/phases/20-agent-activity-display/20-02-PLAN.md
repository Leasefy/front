# Plan 20-02: Agent Result Cards, Chat Integration, and Error States

## Goal

Wire agent execution into the chat flow. When user sends a message that triggers agents, the assistant response includes an agent activity block showing agent badges animating through dispatching → running → completed, followed by collapsible result cards. Failed agents show error state with retry button.

## Requirements Addressed

- **AGNT-04**: Agent result cards displayed inline in conversation (collapsible detail)
- **AGNT-05**: Multiple agents can show as executing simultaneously (integration)
- **AGNT-06**: Error state when agent execution fails with retry option

## Tasks

### Task 1: Agent result card component

**Files:**
- CREATE `src/components/beta/AgentResultCard.tsx` — Collapsible result card

**AgentResultCard component:**
- Header: agent icon + name + status badge + chevron toggle
- Body: collapsible content area with agent result summary (markdown capable)
- Collapsed by default after completion (user clicks to expand)
- When expanded: shows the result data that the agent "returned"
- Border-left color matches agent color
- Compact design that doesn't dominate the conversation

**Error state variant:**
- Red border-left and error icon
- Shows error message text
- "Reintentar" button that triggers retry callback
- Error states are expanded by default (user needs to see what failed)

**Acceptance criteria:**
- Card renders with correct agent metadata (icon, color, name)
- Collapse/expand toggle works with smooth animation
- Error variant shows retry button
- Card integrates visually with the chat bubble stream

### Task 2: useBetaChat agent execution + ChatContainer integration

**Files:**
- MODIFY `src/lib/hooks/useBetaChat.ts` — Add agent execution simulation
- MODIFY `src/components/beta/ChatContainer.tsx` — Render agent activity inline
- MODIFY `src/lib/data/mock-chat-responses.ts` — Link responses to agent scenarios

**useBetaChat changes:**
- `sendMessage` now:
  1. Adds user message
  2. Determines which agents to dispatch (from mock data mapping)
  3. If agents needed: shows AgentActivityIndicator with dispatching badges
  4. Simulates agent execution (staggered starts, 1-3s per agent)
  5. Updates agent statuses: dispatching → running → completed/failed
  6. After all agents complete: starts streaming the assistant response text
- New state: `activeAgentBlock: AgentActivityBlock | null`
- Expose `retryAgent(executionId: string)` for retry on failed agents
- ~10% chance of one agent "failing" for demo purposes (demonstrates error UX)

**ChatContainer changes:**
- Between the last user message and the assistant response, render:
  1. `AgentActivityIndicator` showing agent badges (while agents running)
  2. `AgentResultCard` for each completed agent (after completion, before assistant text)
  3. Then the regular `AssistantBubble` with the response text
- Agent activity blocks are part of the conversation flow (scroll with messages)

**Mock response linkage:**
- Extend `getMockResponse` to return `{ response: string; agents: AgentType[] }`
- cobros → `['cobranza']`
- propiedades → `['pipeline']`
- candidatos → `['pipeline', 'documentos']`
- mantenimiento → `['mantenimiento']`
- contratos → `['documentos', 'comunicacion']`
- reportes → `['reportes']`
- decisiones → `['cobranza', 'pipeline', 'mantenimiento']` (multi-agent)

**Acceptance criteria:**
- Sending a message triggers visible agent execution before response
- Agent badges animate through statuses
- Result cards appear inline and are collapsible
- Failed agent shows error with retry button
- Retry re-runs the failed agent simulation
- Assistant text only starts streaming after agents complete
- All existing chat features (conversations, search, delete) still work

<objective>
Build the ONE genuinely new artifact of this phase: a unified, read-only **case view-model**
(`TenantCase`) plus the `useTenantCases()` aggregator hook that composes the EXISTING real
tenant hooks into a single normalized list. This is a **read projection**, not an engine — it
maps each source row's own `estado`/timestamps into a neutral `TenantCase` and NEVER recomputes
a saldo, an SLA, or a status (PITFALLS 9; PAGO-01 single-source discipline carried from v7-01).

Real sources composed today (R1 scope decision — see below):
- **Pagos abiertos** (REAL): `useMyPaymentRequests()` non-terminal requests
  (`PENDING_VALIDATION` / `DISPUTED` / `REJECTED`) + a current period `NONE`/`REJECTED` from
  `useLeasePaymentInfo()`. `responsable` = "Inmobiliaria". detailLink → `/inquilino/pagos`.
- **Application-journey** (REAL): `useTenantApplications().active` (non-terminal apps — the split
  already folds the contract-signing state for `approved` apps, so contracts are represented
  THROUGH the application case, avoiding a double-counted `contrato` row). detailLink →
  `/inquilino/aplicaciones/[id]`.

Forward-ref types (`pqrs` / `mantenimiento` / `acuerdo`) contribute **zero rows** — they are
rendered as honest "Próximamente" sections by the hub page (v7-03-02), never as empty/fake
`TenantCase` entries. The `CaseType` union still DECLARES them for v7-06/v7-07 forward-compat.

**R1 SCOPE DECISION (locked here):** INCLUDE non-terminal application-journey + open pago cases
as real rows; EXCLUDE terminal applications (rejected/withdrawn/contract_failed/approved-with-
active-contract), terminal payment requests (APPROVED/CANCELLED), and the ACTIVE lease itself
(it is the container/context, not an actionable case). The lease is surfaced as a context header
by the hub, not a row. This is the honest reading of "caso" = something in-motion/actionable; a
tenant fully al día honestly sees a neutral "todo al día" empty-state, not a padded list.

Purpose: Satisfy the CASO-01 backbone (the composition layer) without fabricating any case.
Output: `tenant-case.ts` (types + pure mappers), `use-tenant-cases.ts` (hook), and its test.
No page is edited in this plan.
</objective>
